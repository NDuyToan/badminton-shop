# Architecture Planning Workflow

1. Read project rules and relevant specification sections.
2. Inspect current repository structure.
3. Inspect related modules/components/schema.
4. Identify current patterns to reuse.
5. Map data flow.
6. Define API changes.
7. Define database changes.
8. Define frontend changes.
9. Define tests.
10. Identify security/data-integrity risks.
11. Identify scope creep.
12. Produce:
   - current state
   - proposed design
   - files/modules affected
   - migration plan
   - acceptance criteria
   - risks
   - out-of-scope items

Do not modify code.
