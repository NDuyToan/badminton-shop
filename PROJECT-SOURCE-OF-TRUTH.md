# Project Source of Truth

The uploaded project specification should be kept in the repository as the
authoritative product/architecture planning document, for example:

`docs/project-spec.md`
`docs/PROJECT-SPEC-TRACKER.md` (Living Progress Tracker & Li-Ning Clone Spec)

Recommended instruction:

> Before major implementation decisions, read `docs/project-spec.md` and `docs/PROJECT-SPEC-TRACKER.md`.
> The specification describes the target product and MVP scope.
> Always check `docs/PROJECT-SPEC-TRACKER.md` to see what is completed, what is pending, and update it as you make progress.
> The actual repository code is the source of truth for what currently exists.

If the document is stored under another path, update the references in the
rules/workflows accordingly.
